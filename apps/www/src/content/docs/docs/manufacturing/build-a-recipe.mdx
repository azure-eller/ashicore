Recipes belong to products. Use the product card **Recipe** tab for components and lot-age constraints; use the product card **Production** tab for operation costs.

<p class="po-meta">
  <span class="po-chip">product card</span>
  <span class="po-chip">Recipe tab</span>
  <span class="po-chip">Production tab</span>
</p>

<Aside type="note" title="No standalone BOM screen">
Manufacturing orders use BOM revisions, but the UI does not expose a separate Manufacturing BOM screen. Start from **Inventory > Products**, open the product, then use **Recipe** and **Production**.
</Aside>

<Steps>

1. **Open the product's Recipe tab.** Create or open the product you make, then choose **Recipe**. Select whether the recipe basis is per unit or per batch, and confirm the output quantity or expected batch yield where the product supports batch production.

   <Frame title="<b>Premium Potting Mix</b> · Recipe">
     <div class="mk-pad">
       <div class="mk-rows mk-rows--2">
         <Field label="Recipe basis">Per unit</Field>
         <Field label="Output quantity">1 yd3</Field>
       </div>
     </div>
   </Frame>

2. **Add ingredients and review their estimated costs.** Add each material or subassembly and the positive quantity needed for the recipe basis. A product cannot include itself as a component. Each row shows the component's estimated cost contribution to one finished output unit. For a batch recipe, Ashicore divides the batch quantity by the expected output before calculating that contribution.

   <Frame title="<b>Recipe / Bill of Materials</b>">
     <Grid>
       <thead><tr><th>Component</th><th class="num">Quantity</th><th class="num">Cost</th><th>Requirements</th></tr></thead>
       <tbody>

       </tbody>
     </Grid>

       <Button variant="subtle">+ Add ingredient</Button>
       <Totals rows={[

   Material rates use the current stock cost when available, then the converted default purchase price. A product used as an ingredient uses its current recipe and operation estimate. The underlying rate is used for the calculation but is not shown as another grid column. An em dash means Ashicore cannot resolve the current estimate. Changing a quantity or batch yield updates row contributions and the estimated ingredient and product totals immediately; you do not need to save the draft to inspect it. The operation row in the summary remains the current saved operation cost from the **Production** tab.

3. **Configure variants and constraints.** For a component that belongs to an item family, use **Variants** to choose which active sibling variants may replace it. Enter a positive quantity for each chosen variant in that variant's own unit; Ashicore does not derive this number from the base ingredient or package size. Add a minimum lot-age rule in positive whole days when an ingredient must use lots old enough based on received date.

   <Frame title="<b>Coir Pith</b> · constraints">
     <Grid>
       <thead><tr><th>Type</th><th>Value</th><th>Effect</th></tr></thead>
       <tbody>
         <tr><td>Lot age</td><td>30 days</td><td>Picking prefers eligible old-enough lots.</td></tr>
       </tbody>
     </Grid>
   </Frame>

4. **Add operations and save.** Move to the product **Production** tab to add operation cost rows. Choose the resource, crew size, planned minutes, and loaded rate. Saving a changed recipe creates a new current BOM revision; saving the same payload again leaves the current revision in place. Older revisions remain available for history.

</Steps>

<Aside type="caution" title="Orders snapshot the current revision">
Changing the recipe later creates a new revision for future manufacturing orders. Existing orders keep the components and operation costs they copied at creation.
</Aside>

<Aside type="note" title="Recipe history does not snapshot estimates">
The cost column shows estimates from current item costs. Recipe history preserves the saved formula and operation inputs, but it does not store or display a historical component-cost snapshot.
</Aside>
