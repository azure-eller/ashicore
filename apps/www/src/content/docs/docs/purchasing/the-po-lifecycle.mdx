Every saved purchase order moves through three receiving-progress statuses — <Pill status="not_received" /> <Pill status="partial" /> <Pill status="received" />. Creating the order immediately books expected supply; status only tracks receiving progress.

## Explore each status

Select a status to see what it means, what's allowed, and where it can go next.

<PoLifecycle />

<Aside type="note" title="There is no “cancelled” status">
An order is removed by **deleting** it, which is possible at any status. Deleting releases the order's remaining expected supply, and if stock was already received, the part still on hand is removed from stock — see [what happens when you delete](#what-happens-when-you-delete-an-order).
</Aside>

## What happens when you receive

Receiving is the most consequential action in purchasing — it's where a promise on paper becomes real, costed, traceable stock. It only ever adds: you can receive more, never "un-receive." One receipt does five things, in order:

<Steps>

1. **Each received line writes inventory history.** Lot-tracked items get a new lot for the received quantity. Lot-untracked items append to their internal shared lot. Receipts arrive as **available**; move a lot to **blocked** afterward from inventory if it needs to be held out of use.

2. **The lot is costed at the line's landed cost per stocking unit.** Any by-value additional costs you entered before receiving are already baked into that value.

3. **The receipt becomes permanent history.** Received lines can't be removed, and even deleting the order later keeps every receipt event in item history — only stock still on hand is backed out.

4. **Expected supply for what you received is released.** Planning instantly reflects what actually landed instead of what was still due.

5. **The status advances only when the receipt completes the order.** Receiving part of a not received order makes it <Pill status="partial" />. Receiving another partial batch keeps it <Pill status="partial" /> until every line is complete, then it becomes <Pill status="received" />.

</Steps>

<Aside type="caution" title="You can't receive more than remaining">
The receive dialog caps each line at its remaining quantity. A larger value is flagged invalid and cannot be submitted. Increase the ordered quantity first if more stock arrived than the order currently allows.
</Aside>

<Aside type="note">
Blank quantities are ignored, and a received quantity must be greater than zero. Marking an order **Received** from the status control isn't a shortcut that skips receiving — it opens the same receive dialog and prefills every remaining line. If you leave the prefill unchanged, the order completes; if you reduce or clear rows, it records only those quantities and may remain <Pill status="partial" />. Stock lands in the **Receive into** location you choose, while expected supply is released from the default planning location.
</Aside>

## Valid & invalid transitions

These are the only moves the system allows. Anything not listed is blocked to protect inventory history.

| Action | From | To | Notes |
|--------|------|----|-------|
| Create | <span class="po-tok po-tok--muted">New</span> | <Pill status="not_received" /> | Registers the ordered quantity as expected supply. |
| Receive some | <Pill status="not_received" /> | <Pill status="partial" /> | Each received line writes stock history; tracked items get a new lot. |
| Receive all | <Pill status="not_received" /> | <Pill status="received" /> | The receive dialog is prefilled with the remaining quantities. |
| Receive another partial batch | <Pill status="partial" /> | <Pill status="partial" /> | More stock arrives, but a remainder still exists. |
| Receive the rest | <Pill status="partial" /> | <Pill status="received" /> | Completes the remaining lines. |
| Add a line / increase a quantity | <Pill status="received" /> | <Pill status="partial" /> | Reopens the remainder. |
| Delete | <span class="po-tok po-tok--muted">Any status</span> | <span class="po-tok po-tok--muted">Removed</span> | Releases expected supply; received stock still on hand is removed from stock. |
| Reduce below received | <span class="po-tok po-tok--muted">—</span> | <span class="po-tok po-tok--no">Blocked</span> | A quantity can't drop under what's already received. |
| Remove a received line | <span class="po-tok po-tok--muted">—</span> | <span class="po-tok po-tok--no">Blocked</span> | Receipt history must be preserved. |

## What happens when you delete an order?

Delete is always available from the order card's **⋯** actions menu, and the confirmation dialog states exactly what the delete will do before you commit:

- A <Pill status="not_received" /> order is simply removed, and its expected supply is released.
- A <Pill status="partial" /> or <Pill status="received" /> order also has its received stock **that is still on hand** removed from stock.
- Quantities already used in manufacturing, sales, or adjustments are **kept, with their history and received cost intact** — the dialog lists them separately.

The receipt events themselves are never erased: item history keeps the original receipts alongside the compensating removal, so traceability and costing stay auditable.

<Aside type="caution" title="Bills in your accounting provider">
Deleting an order here never deletes a bill that was already sent to your accounting provider. The dialog warns you when one exists — delete the bill in the provider too if it shouldn't be paid.
</Aside>
